For my third enhancement, I continued working on the Weight Tracker application I originally developed for CS-360. The application was built in Android Studio using Java and SQLite. It allows users to create an account, record their daily weight, set weight goals, and track their progress over time. I chose to continue enhancing this application because it had lots of great opportunities for enhancements in all three areas, especially Databases.

For this enhancement, I focused on improving the application's database operations, security, and overall efficiency. Although the original database worked, there were several areas where the design could be improved. One of the first changes I made was implementing password hashing and salting. Originally, user passwords were stored as plain text, which presented an obvious security risk. I initially implemented PBKDF2 with SHA-256 to protect passwords, along with functionality that allowed existing users to transition away from plain-text storage. I also added a feature that allows users to change their passwords by verifying their current password before saving the replacement. One of the bigger challenges I encountered was the performance impact of password hashing. While PBKDF2 improved security, the number of iterations I was using caused login attempts to take 4-7, seconds, which is unacceptable. I eventually implemented Argon2id for new password hashes while maintaining compatibility with the existing PBKDF2 hashes. This allowed existing users to migrate to the new approach without losing access to their accounts. Working through this problem helped me better understand the balance between security and performance. A solution can be technically secure but still need improvement if it negatively affects the user experience.

I also improved the way the application stores and retrieves weight records. Previously, dates were stored in an MM/dd/yyyy format, which required more complicated SQL queries to sort records chronologically. I changed the database to store dates using the ISO format, yyyy-MM-dd, and updated the application's date handling and analytics to support the change. I implemented a database migration to preserve existing records rather than requiring users to start over. Another improvement involved reviewing the database indexes. I discovered that an index I had manually created was redundant because SQLite already maintained an index for the table's unique constraint.

I improved how goal weights and account information are saved. Previously, the application deleted existing records before inserting updated information. I replaced that approach with logic that updates an existing record and only inserts a new one when necessary. This reduced unnecessary database operations and avoided the risk of losing an existing record between deletion and insertion.

Throughout this enhancement, I gained a better understanding of database design, data integrity, security, and performance optimization. I also became more comfortable using Android Studio's Database Inspector to examine indexes and query execution plans instead of assuming that a particular approach was efficient. I really enjoyed this enhancement specifically because the password salt:hash was a unique challenge that allowed me to make decisions that balanced security and speed.

This enhancement demonstrates several of the computer science program outcomes, particularly my ability to design and evaluate computing solutions, apply appropriate tools and techniques, and develop software with a security mindset. Compared to the original version of the application, the enhanced database is more maintainable, uses stronger credential protection, and handles stored information more efficiently. More importantly, this process helped me understand how to evaluate an existing application, identify weaknesses, and make improvements without unnecessarily rebuilding functionality that already works.
