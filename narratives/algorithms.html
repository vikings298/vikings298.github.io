1. Artifact Description

The artifact I chose is the Weight Tracker Android application I created earlier in the Computer Science program for a mobile development course. The app allows users to create an account, log their weight, set a goal weight, and view their previous entries. For this enhancement, I focused on adding more useful algorithms and data structures to the application.

2. Justification and Enhancement

I chose this artifact because the original app already collected weight data, but it did not really do anything with that data besides display it. I thought this gave me a good opportunity to add features that actually analyze the user's progress.

I added an AnalyticsService that handles six new features: a recent weight average, weight trend, current logging streak, recent weight change, goal estimate, and plateau detection. I also used different data structures where they made sense, such as a Deque for working with recent weight entries and a HashSet for checking dates when calculating a logging streak. Overall, the enhancement made the data that was already being collected much more useful.

3. Course Outcomes

This enhancement mostly focused on course outcome 3 because I had to design solutions using algorithms and decide which data structures made sense for each problem. There were also some trade-offs that I had to think through, especially when dealing with users who do not log their weight every day.

I also think this enhancement supports course outcome 4 because I used the programming skills and techniques I have learned throughout the program to add useful features to an existing application. At this point, I do not think I need to make any major changes to my original outcome coverage plan.

4. Reflection

One thing I learned during this enhancement was that the logic behind a feature can get more complicated once you start thinking about how someone will actually use it. For example, I originally thought of the moving average as a seven-day average, but that does not really work if the user skips days. I decided it made more sense to use the seven most recent entries instead.

The logging streak also took some thought. I did not want someone's streak to reset just because they had not logged their weight yet that day. Working through situations like these made me think more about the actual data and edge cases instead of just getting an algorithm to run. I think that was the most valuable part of this enhancement.
