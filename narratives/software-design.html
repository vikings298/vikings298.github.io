Software Design and Engineering

Weight Tracker Android application

← Back to portfolio

The artifact I selected is a Weight Tracker Android application that I created two terms ago for a mobile development course. The app allows users to create an account, log their weight, set a goal weight, and track their progress over time. It was built in Java and uses SQLite to store user information, weight entries, goals, and other account information.

2. Why did you select this artifact? How was it improved?

I selected this artifact because it is a full-stack application with several areas that I can improve. It has a frontend UI, backend business and application logic, and a database. It is also something that is easy to demonstrate in my ePortfolio and explain what I changed and why.

For this enhancement, I focused on the architecture of the application. Originally, the Activity classes were doing too much. They handled the UI, business logic, and direct database interactions, which created a lot of coupling between different parts of the app. I refactored this by adding separate model and service layers. Models now represent data such as users, weights, and goals, while services handle the logic between the Activities and database.

This gave each part of the application a more specific responsibility. The Activities can focus more on the UI, while the services handle application logic and DatabaseHelper handles the database. This should make the application easier to maintain and build on as I continue enhancing it.

3. Did you meet the planned course outcomes?

I believe this enhancement met the course outcome I planned to address for software engineering and design. I used established software design principles to evaluate an existing application and improve its architecture. I had to consider separation of concerns, coupling, and how responsibilities should be divided between classes.

My outcome plan has not changed significantly. This enhancement focused mostly on software engineering and design, while my later enhancements will give me opportunities to demonstrate more of the algorithms, database, and security outcomes.

4. Reflection

One of the biggest things I learned was that a refactor can be completed in stages. I was able to change one part of the application, test it, and then continue instead of trying to redesign everything at once.

The more difficult part was figuring out what was actually wrong with the existing architecture. The application already worked, so I had to think beyond whether the code functioned and look at principles such as separation of concerns and coupling. I learned the value of keeping classes focused on one main responsibility and creating a clear structure for how different parts of the application communicate.

Overall, I came away from this enhancement with a better understanding of how to architect software rather than just how to make it work.
